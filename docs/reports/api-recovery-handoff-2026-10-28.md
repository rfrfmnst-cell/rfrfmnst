## الإصلاحات

- تحميل ts-jest صراحة من حزمة API مع tsconfig معلوم، وحد عاملين لـJest.
- إغلاق تطبيقات اختبارات HTTP وإضافة فحوص الترويسات وCORS والجاهزية.
- نقل ملفات اختبار التخزين المؤقتة إلى `tmpdir` بدل مسار بيئة قديمة ثابت.
- توفير `pnpm verify` فعلي وCI خاص بـAPI، دون أسرار أو نشر أو اتصال إنتاج.
- إضافة `/api/readiness` المحمية بسر خادم. لا اتصال DB عند غياب الإعداد أو
  الاعتماد. تحافظ `/` و`/api/liveness` على سلوكهما السابق دون حاجة لقاعدة.
- ربط pg اختياري بـ`API_DATABASE_URL` مستقل لدور قراءة فقط، مع TLS موثق
  للاتصال البعيد وحوض اتصال واحد ومهل محدودة ومشاركة الفحوص المتزامنة.
- التحقق من الجداول الستة الأساسية وصلاحية SELECT من الكتالوج ضمن
  `BEGIN READ ONLY` وإنهاء الفحص بـ`ROLLBACK`؛ لا قراءة بيانات شخصية.
- تثبيت pg وtypes بالإصدار 8.23.1، وإضافة 118 سطرًا إلى lockfile فقط؛ حُفظت
  كل سجلات التبعيات والنسخ القديمة الموجودة في main دون إعادة حلها.

اختبار PostgreSQL الفعلي شمل إقلاع الحزمة الإنتاجية ورفض الوصول غير المصرح
به، رفض المخطط الغائب، القبول مع الجداول والصلاحيات، منع دور الفحص من INSERT،
رفض سحب SELECT ثم التعافي بعد إعادتها، رفض نقص جدول، وبقاء الحياة مستقلة.
أزيلت حاويات الاختبار المملوكة للأداة وحدها، ولا قاعدة إنتاج مستعملة.

حدث فشلان أثناء تجهيز اختبار القاعدة، لا في الفحوص النهائية: انتظار خادم
PostgreSQL المؤقت عبر Unix socket قبل جاهزية TCP، وتشغيل تجربة متزامنة مع
إعادة تغليف الحزمة. عُدّل الانتظار إلى TCP، وأعيد الاختبار بعد انتهاء البناء؛
نجحت الدورة الأخيرة. لا تُعرض المحاولات السابقة كنجاح.

## الاستكمال ومتطلبات التشغيل

تعليمات الضبط والحدود في
[جاهزية قاعدة API](../../sites/api.rfrf.net/API_DATABASE_READINESS.md).
إعادة التحقق من جذر المستودع:

```sh
cd sites/api.rfrf.net
pnpm install --frozen-lockfile
pnpm verify
pnpm test:database
```

تحتاج تجربة تكامل مع قاعدة المنصة الحقيقية إلى هدف معتمد ودور قراءة فقط
و`API_DATABASE_URL` خاص، و`READINESS_PROBE_SECRET` قوي محفوظ خارج Git،
وTLS مع `sslmode=verify-full` للعنوان البعيد. هذه القيم غير متاحة في البيئة.
لا تُرسل الأسرار في المحادثة ولا توضع في المتصفح. لم تتغير صلاحيات الإنتاج.

نجاح الفحص يثبت الاتصال ووجود الجداول وإمكانية SELECT فقط، ولا يثبت الأعمدة
والقيود وRLS لكل رحلة أو سلامة بيانات العملاء والطلبات أو دورة دفع وشحن.
الـAPI المنفصلة ما زالت لا تنفذ مسارات أعمال السوق؛ تبقى في تطبيقات BFF.
الاختبار مع بيانات اصطناعية كاملة والمصادقة والمزودين يحتاج staging مستقلًا
وموافقة المالك. لا جاهزية إطلاق إنتاج أو نشر تلقائي في هذه الدفعة.

تبقى ملفات الموردين وتسجيل الدخول لعمل Copilot الحالي، وتصميم V2 في PR #10
متوقفًا. المراجعة التالية يجب أن تبدأ من هذا الفرع وتقرأ نتائج CI للـSHA
المرفوع، دون دمج أو نشر أو migration ما لم يأذن المالك صراحة.
