# جاهزية API وقاعدة المنصة

هذه إضافة تشخيص محدودة، وليست تنفيذًا لـAPI V2 أو نقلًا لمسارات الأعمال.
يبقى `/` و`/api/liveness` كما كانا، ويعملان دون قاعدة بيانات. يبقى Tap وOTO
والمصادقة وواجهات الموردين والعميل والإدارة دون تعديل في هذا الفرع.

## فحص الخادم

`GET /api/readiness` يتطلب ترويس `x-readiness-probe-secret` مطابقًا
لـ`READINESS_PROBE_SECRET` قوي بطول 32 إلى 512 حرفًا. لا تضعه في متغير
عام أو المتصفح أو سجل الطلبات. غياب الإعداد يعيد 503؛ اعتماد مفقود أو خاطئ
يعيد 401 دون فتح اتصال قاعدة. ردود الخدمة ثابتة ولا تعرض DSN أو أخطاء pg.

يتطلب الفحص `API_DATABASE_URL` مستقلًا لدور PostgreSQL مصرح له بالقراءة
فقط. لا يستعمل `DATABASE_URL` الخاص بتطبيقات BFF تلقائيًا، ولا مفتاح خدمة
Supabase. عنوان قاعدة Supabase الخاصة بمحاولات Tap ليس بديلًا لقاعدة المنصة.
لا تُنشئ أو تمنح دورًا في الإنتاج ضمن هذا PR؛ يجهز المسؤول اعتمادًا محدودًا
بعد الموافقة على الهدف. يجب إعادة تشغيل العملية عند تغيير اعتماد الفحص.

الاتصال البعيد يتطلب `sslmode=verify-full` وشهادة موثوقة من إعداد TLS
المعتاد. الاتصال دون TLS مسموح على loopback فقط لاختبارات محلية معزولة.
لا يضاف `rejectUnauthorized=false` أو تعطيل تحقق الشهادة.

حوض الفحص باتصال واحد، ومهلة اتصال 2.5 ثانية ومهلة استعلام 2.5 ثانية،
مع مهلة PostgreSQL للاستعلام ثانيتين والقفل ثانية. طلبات الفحص المتزامنة
تشارك عملية واحدة. يبدأ الفحص `BEGIN READ ONLY` وينهي دائمًا بـ`ROLLBACK`؛
يحرر الاتصال ويتخلص منه عند خطأ، ويغلق الحوض عند إغلاق التطبيق.

يقرأ الفحص كتالوج PostgreSQL فقط ليتحقق من وجود جداول `public.users` و
`customers` و`suppliers` و`rfqs` و`quotes` و`orders` وصلاحية SELECT للدور،
ومن أن المعاملة للقراءة فقط. هذه الأسماء مأخوذة من `@@map` في مخطط Prisma
الحالي. لا يقرأ صفوف عملاء أو موردين أو طلبات ولا ينفذ migrations أو seed.

نجاحه يعيد `DATABASE_CORE_SCHEMA_READY` مع نطاق
`database-connectivity-and-core-schema`. نقص جداول أو صلاحيات يعيد 503
`DATABASE_SCHEMA_UNAVAILABLE`، وفشل الاتصال يعيد 503 `DATABASE_UNAVAILABLE`.
لا يثبت نجاحه توافق الأعمدة أو القيود أو RLS لكل حالة استخدام أو سلامة بيانات
الأعمال أو اكتمال تسجيل الدخول والدفع والشحن؛ يجب اختبار هذه الأمور مستقلة.

## التحقق المحلي المعزول

من نسخة نظيفة بلا ملفات أسرار، استخدم Node.js 24 وpnpm 11.6.0:

```sh
pnpm install --frozen-lockfile
pnpm verify
pnpm test:database
```

الأمر الأخير يحتاج Docker محليًا وبناء `hostinger-runtime` مكتملًا. ينشئ
حاوية PostgreSQL 17 جديدة باسم عشوائي، ببيانات اصطناعية فقط ومنفذ loopback
مؤقت، ويشغّل الحزمة الإنتاجية مقابل دور لا يملك الكتابة. يختبر المخطط الغائب
والدور المصرح له وسحب SELECT ونقص جدول، ثم يزيل حاويته وحدها. لا يقبل DSN
من المستخدم ولا يستعمل قاعدة قائمة أو بيانات إنتاج أو مزود دفع أو شحن.
الصورة مثبتة ببصمة؛ لا يوجد volume دائم أو اشتراك خارجي.

لا تُشغّل هذه الأوامر كأداة نشر إنتاج. لا دمج أو Hostinger أو تغيير إنتاج
قبل موافقة المالك. يظل تصميم V2 في PR #10 متوقفًا للمراجعة.
